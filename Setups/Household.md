# Household and everyday life

Start with the structure that matches the need. Simple lists should stay simple.

| What to track | Where | Example |
|---|---|---|
| Groceries / packing / gift ideas | List note with checkboxes | /list groceries add milk and 6 eggs |
| Home improvement ideas | List until an idea becomes a committed project | /list home ideas add repaint hallway |
| A room renovation or move | Project with scope, budget if supplied, and tasks | /kickoff renovate spare bedroom |
| Appliances / electronics / tools | Item note with receipts/manual links | /item dishwasher purchase details |
| Returns / warranty follow-up | Documented dates on the item; linked task for action | Suggest a return task before the actual deadline |
| Repairs / regular maintenance | Item history plus maintenance tasks | Boiler service, filter replacement, car inspection |
| Subscriptions / memberships | Reference or item note plus renewal/cancellation task | Record real terms and next review date |
| Travel | Project for a complex trip; reusable packing list | Link booking references and preparation tasks |
| Household administration | Admin tasks and source reference notes | License renewal, records request |
| Recipes / meal planning | Reference notes and a weekly note/list | Link ingredients to a grocery list |
| Loans to/from people | Item note linked to a person and agreed return task | Borrowed drill, lent textbook |
| Personal goals / learning | Project, practice tasks and optional accomplishments | Finish a course or build a portfolio project |

`/list` uses Lists/ and tag list. category can be groceries, packing, wishlist,
home-improvement, gifts, reading or your own value. A checked grocery entry does
not need a separate completed task. If an entry gains a deadline/owner/follow-up,
ask to turn it into a task and replace the original checkbox with that link.

`/item` uses neutral Item by default, or Purchased item for purchase/warranty
details. Both use Items/ and tag item. Ownership and area are not presumed. category describes the thing; status can be owned,
borrowed, lent, sold, donated, returned or disposed. Store price and currency as
supplied. Keep warranty/return terms, exact dates and their source rather than
assuming a standard period. Maintenance and repairs are append-only dated history.
Shared school/work equipment can use the same type with its appropriate area.

Put receipt PDFs/images and manuals in Attachments/ and link from the item note.
The AI tools currently read Markdown, not attachments. Provide the relevant text
when requesting extraction. A stored receipt is not automatically included in an
AI search. Do not duplicate sensitive document contents just to make search work.

Fieldbook records follow-ups; it does not make purchases, cancel subscriptions,
file claims or contact vendors. Calendar events and recurring instances remain
in the calendar/TaskNotes system you actually use. No new automation starts merely
because you recorded a date.
