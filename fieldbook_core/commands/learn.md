description: Save reusable supplied knowledge as a Reference note (/learn <what you found>)
---
Input: $ARGUMENTS. Follow AGENTS.md. Get today's local date when needed.
A reference can be a recipe, study explanation, instructions, policy, query or
other knowledge in any area. A technical system is not required.

1. Find an existing Reference note on the same subject. Offer to extend it rather
   than duplicate it; preserve source text, earlier log entries and custom fields.
2. Use Templates/Reference.md in Reference/. Resolve area/projects using the shared
   defaults. Set kind or topics only when clear/useful (for example recipe, concept,
   how-to, instructions, query); otherwise leave them empty. Do not ask for a system
   name, organization or verification date just to fill a template.
3. Write a specific title, a short Summary and supplied Details, with source links
   when supplied. Preserve quoted text, queries and commands; add no invented facts.
   Add a dated Log line. Do not store passwords, tokens or keys; tell the user when
   one was omitted.
4. For technical material only, add systems when supplied/relevant and reuse known
   spellings. A verified date needs the user's confirmation of testing. For an
   explicit statement that a person supports a system, offer/requestedly update
   their optional supports field after resolving their identity. That fact alone
   does not require a separate Reference note or a professional/report profile.

Use notebook_write for requested changes. Reply with the note/person link and a
brief result; mention any unresolved source or identity issue.
