---
name: handover-planning
description: Prepare a sourced handover, onboarding brief or coverage plan for a project, responsibility, household, course group or work transition.
---

Establish the subject, recipient and coverage/transition period from the request.
Read the relevant project, tasks, decisions, references and people links. Draft:
current outcome/state, immediate next actions and actual owners, upcoming dates,
open risks/decisions, operating instructions already documented, and source links.
Separate confirmed facts from unanswered questions. A suggested owner is not an
accepted commitment. Do not copy passwords, credential material, private reviews
or unrelated personal notes. A role specialization in fieldbook.json helps select
questions only for matching work context; it does not change access permissions or authorize domain actions.
Suggest missing documentation or an actionable task when it would make the handover
usable. Save a Notes/ or Reports/ draft only as requested, via notebook_write.
Never send it, close tasks, change owners, or run operating procedures merely
because a handover was requested.

For onboarding or temporary coverage, add a compact table of confirmed ownership,
source commitment, next action, handoff/check-in date and open question. Separate
recipient suggestions from accepted ownership. Include documented access needs
without copying credentials or performing access changes. Use this same structure
for household coverage, group coursework and work transitions; formal personnel
feedback belongs only in an explicitly requested manager workflow.
