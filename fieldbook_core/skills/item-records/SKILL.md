name: item-records
description: Record owned, borrowed or shared items in any area, with optional purchase, warranty and maintenance details.
---

Use Templates/Item.md by default in Items/ for owned, borrowed or shared equipment,
books, tools or other possessions in any area. Leave ownership/status unknown until
supplied. Resolve area from the request/project/configured default, never from the
item type alone. Use Templates/Item - Purchased.md when recording a purchase, receipt
or warranty; it adds commercial details without changing the item tag or folder.
For an existing item add only the requested fields/sections, preserving history.
Do not require purchase, warranty or maintenance details for a borrowed textbook.
Match the exact item/model before editing. Record supplied purchase date/vendor,
price/currency, brand/model, location or owner if useful, and links to receipts and
manuals. Do not request serial/account numbers unless needed for the user's purpose.
AI notebook tools do not parse PDF/image attachments; use text the user supplies
or ask them to transcribe the relevant receipt/warranty details. Never claim to have
read an inaccessible attachment. Store attachments manually under Attachments/.
Warranty expiry and return windows come from documented terms; do not infer coverage
or calculate a date from an assumed policy. Record uncertainty and the source.
Append repairs/maintenance with dates. Suggest a task for an actual return deadline,
renewal or maintenance action if useful, but create it only on request/acceptance.
Use task links instead of duplicating due dates in unchecked body lists. Capture is
not an insurance valuation or proof of coverage; preserve the actual document.
Never buy, return, cancel, register or contact a vendor as part of recording an item.

When reviewing dates, show return_by and warranty_end separately, with the supplied
receipt/terms source. A past date does not establish eligibility, coverage, a
completed return or a required purchase. Suggest a reminder task only for a chosen
action, linking the existing item and using the actual action deadline. Preserve
historical purchases/repairs and check for an existing follow-up first.

## Optional agreements and renewals

/renewal uses Item - Agreement in any setup. Keep renewal_date,
cancellation_notice_by and expiration_date distinct. Read the supplied terms before
recording dates; unknown notice rules stay unknown. Review Upcoming dates for each
date type. Suggest a related action when useful; never cancel, renew, purchase or
contact anyone automatically. Preserve existing item history and attachments.
