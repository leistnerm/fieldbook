---
name: people-context
description: Find people and prepare sourced contact context across personal, work and school notes; use for /people or relationship follow-up.
---

Use notebook_query with kind person; use fuzzy title/alias search to resolve a
named contact. For a broad /people request show a concise directory grouped by
supplied relationship or area, then the actions available: view context, prep a
meeting, record a fact, check links, or create a person. Do not dump private bodies
or employee reviews into a directory. A manager is not necessarily the user's
manager. In this vault relationship self identifies the user and report identifies
their direct reports. Manager links describe broader reporting lines and are
optional for tracker scope. Confirm relationships rather than inferring them.
For tracker identity setup use the exact usernames labels in INTEGRATIONS.md;
never infer account identities from display names.
For a named person, confirm identity if there are multiple candidates. Find
backlinks and structured person associations; read the relevant recent notes.
Summarize recorded relationship, current shared projects, open commitments and
last meaningful interaction with source links. A stale commitment is unverified,
not automatically broken or completed. Do not infer personality, health, protected
traits, performance ratings, or reporting relationships from chatter.
Basic contacts work in every setup; work fields are optional. /1on1 is a general
conversation in any setup; /coach is explicit manager coaching with role/report
checks. Neither changes the person's template simply by being used. Offer a useful missing
link or follow-up without changing it. A directory/context request never authorizes
creating contacts, linking every mention, or sending a message. Requested changes
use notebook_write after checking aliases and exact identity.

For requested creation use Templates/Person.md by default, in every setup. Use
Templates/Person - Professional contact.md when the user requests a professional profile
(peer, customer, vendor, instructor, partner), and Templates/Person - Direct report.md only
when they identify someone as their direct report and work + people-manager is
enabled. Otherwise use Person with the supplied relationship report; explain the
optional manager setup only if the user wants that layout or workflow. Work setup alone never selects
the report template. All three create the same person tag in People/. Use the
relationship supplied by the user; never infer report from a title or team.
For the user's own record, start with Person and set relationship self; add their
requested goals/career sections without treating them as a report. Contact fields
emails/phones are lists of supplied, optionally labeled values; retain older
workEmail/otherEmails/workPhone/otherPhones fields when updating existing notes.
Templates start new notes, not replacements for existing records. Add only requested
sections to an existing person, preserving their facts, logs and links. See the
People section of Note types.md for examples and optional report employment fields.

In the template picker, specialized layouts are grouped by their base type:
Person - Professional contact and Person - Direct report. Person stays the default;
a chosen profession or work setup does not imply a report relationship. Apply only
the requested sections when enriching an existing note, preserving its history.
